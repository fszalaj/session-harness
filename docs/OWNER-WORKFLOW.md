# Maintainer role workflow

This is an optional workflow the maintainer is evaluating. It does not configure
other users, publish account settings, or establish that a particular model mix is
optimal. Keep selected routes, credentials, monetary limits and machine-specific
instructions in private configuration. Corporate transfer instructions are private.

| Responsibility | Preferred family | Boundary |
| --- | --- | --- |
| Manage a session | Codex or Claude, matching the hosting client | Plan, integrate changes and verify acceptance |
| Help plan and check the result | The other of Codex and Claude | Fresh bounded review; no shared conversation history |
| Narrow semantic judgments | Jev | Typed classification, selection and rubric scores |
| Produce bounded implementation | Gemini or reviewed DeepSeek Flash | Manager inspects the returned code and runs tests |

The manager remains accountable for broader decisions. Deterministic rules do not
need a model call. Batch independent Jev questions over shared state when useful;
an extra classification call for every trivial task can increase cost and latency.
Two independent permitted families still review material plans. The supervising
model's agreement is not a substitute for tests, and workers never approve their
own implementations. Use a fresh verifier for substantial integrated changes.

Resolve the newest eligible generation from current catalogs and reviewed evidence.
Keep the manager at supported xhigh, or the highest advertised level below max.
Ordinary native workers and reviews use medium when supported. OpenRouter effort
labels must come from the model's reasoning metadata: some models expose low and
high without medium. Prefer the highest supported level below medium for ordinary
work and raise it for a concrete difficult task or failed attempt. Record that
selection rather than calling it the provider's default. Max remains an explicit
task-level exception. A dated private coding policy must be reviewed again before
renewal or adding a successor; a model name containing Flash is not quality proof.

## Execution and billing boundaries

Native Gemini execution currently uses the Antigravity adapter. Standalone Gemini
CLI discovery does not establish protected execution. Use an explicit admitted
native worker selection for this workflow; do not silently switch a stopped task
from free, native or paid billing to another route. Keep existing liabilities.

OpenRouter `api coding-run` returns supervised text, including proposed code. It
does not edit files, run a repository agent loop, deploy or supply independent
review approval. The manager applies inspected changes and runs relevant checks.
Use a reviewed private `--policy`, the selected key's private environment and the
existing monetary authority. Two keys do not create independent provider families
or shared accounting between otherwise separate ledgers.

Copilot is a billing service, not a model family. The installed adapter currently
supports supervised text; Auto does not prove Claude or Gemini selection. Even an
exact selectable model does not, by itself, add independent reviewer support.
A session with Codex plus only this Copilot adapter and Jev lacks two independently
verified reviewer families. Report the gap before gated implementation; do not
invent model identities or silently weaken the review policy.

## Evaluate before recommending

Compare workers on identical bounded tasks with deterministic acceptance tests.
Record correctness, elapsed wall time, actual returned model, requested versus
reported effort, billed API receipts and separately measured native quota use.
Use isolated test environments; inspect generated code before executing it.
Do not convert subscription tokens or percentage points into invented USD costs.

Transport/schema tests and a successful catalog lookup establish compatibility,
not end-to-end quality. Paid testing needs explicit monetary admission first.
A small coding probe can show that a route works or reveal a defect; it cannot
establish a globally optimal allocation. Prefer the simplest division that passes
the project's tests, and keep the manager's review cost in the comparison.
